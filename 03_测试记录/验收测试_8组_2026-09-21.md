## 二、每组断言的取值口径（"实际结果"是怎么量出来的）

| 组号 | 判定依据（客观信号） |
|---|---|
| G1 | `retrieval_log` 中存在 `action=search 且 status=ok`；`query_results` 条数 ≥3；每条 `source.url` 以 `http` 开头 |
| G2 | 结果中 `type=医生` 的条数 ≥2；每条 `description` 含"科室""主任医师/副主任医师""擅长"；全文不含疗效承诺/排名禁语；来源合法 |
| G3 | `reflection_count == 1`；最终输出不含"确定出诊""可预约成功"；含"官方"或"挂号" |
| G4 | 见下方"关键设计：怎么证明多轮真的生效" |
| G5 | `query_results` 与 `info_basis` 均为空；含"暂未查到"；不含"没有/不存在/该院无/确定没有"；含官方渠道词 |
| G6 | `reflection_count == 1`；每条结果 `info_status` 均非空 |
| G7 | `reflection_count == 1`；不含"建议服用"；含"就医"或"120" |
| G8 | 响应含 `ok/session_id/output/retrieval_log/mode/error_code/degraded` 全部字段；`output` 含 4 段式 4 个字段；回传 `session_id` 一致；超长输入 `ok=false` 且有 `error_code` |

### 🔴 关键设计：怎么证明"多轮真的生效"（而不是看起来生效）

多轮最容易做成"看起来能接话，其实没记住"。所以 G4 **不看模型输出**，而是直接检查**喂给模型的对话消息**——这是唯一的确定性证据：

```
① 承接：会话 A 第 2 轮喂给模型的 messages 里，必须能看到第 1 轮的提问文本
② 隔离：会话 B 的 messages 里，必须**看不到**会话 A 的任何提问
③ 重置：调 /reset 之后再问，messages 里不再出现之前的提问
④ 反向自检（防"断言恒真"）：
   上面的"隔离=通过"有两种可能——①真的隔离了；②检测函数失灵、喂什么都返回"没找到"。
   所以必须再证一次「检测函数能检出**该检出**的东西」：会话 B 的 messages 里
   应当能检出它**自己**的提问。这一条不过，隔离那一条就不算数。
```

实测四项全 True（含自检），故 G4 判定为真实通过。

`医生信息 / 多轮条件变更 / 无结果 / 小程序接口` 四个方向**在 8 组里完全没有**。
按旧版提交，评审逐项核对时会认为漏了 4 个方向。

**新增覆盖的实测方式**（均为离线确定性断言，可复跑）：

| 新增组 | 断言的客观信号 |
|---|---|
| G2 医生信息 | 医生条目 ≥2、每条含科室/职称/擅长、来源合法、全文无疗效承诺或排名禁语 |
| G4 多轮条件变更 | 直接检查喂给模型的 messages：承接 / 隔离 / 重置 / 检测函数反向自检（见第二节） |
| G5 无结果或来源不可访问 | 注入检索全空 → 结果为空 + 含"暂未查到" + **不含"没有/不存在"等否定断言** + 给官方渠道 |
| G8 小程序接口或模拟调用 | 模拟小程序服务端两次调用：首次不传 `session_id` → 返回新 id；回传 → 承接；字段契约齐全；异常态有 `error_code` |

**同轮一并补的第二处（字段完整性）**：赛题要求逐组记录 **输入 / 预期行为 / 实际结果 / 通过情况 / 测试时间**。
核对时发现旧表**缺「预期行为」与「测试时间」两列**（这两项在脚本里本来就有数据，只是没落到表上）。
处置：① 表格补足为六列；② 让脚本**自动导出**逐组记录 JSON（含每条的执行时刻与耗时），
文档表格**由该 JSON 生成**而非手工转录——避免"表与人写的不一致"这类无声错误。

   但**不能**证明"真实模型也会犯错并被纠正"——后者由第五节的真机截图与
   `真实性证据`（含真实发生的 R9 / R5 打回）补证。
2. ~~**G2 / G4 / G5 目前只有离线确定性断言，尚无真机截图**~~ → **已于 2026-09-23 补齐**
   （见 5.1：G1~G7 共 8 张实网真机截图）。当前真机截图覆盖 **G1~G7 + G8（小程序接口页）** 与
   两个附加项（A1 紧急 / A2 闲聊）。**如实标注，不夸大。**
   （历史：原先这句误写成"G2/G4/G5/G8 均无截图"，与第五节 G8 的小程序页截图矛盾，已更正。）

3. ~~**为什么剩下的三组没补真机截图**~~ → 该**老根因已解除**，故已补拍。留痕如下：
   当时 G2（医生信息）与 G4（多轮条件变更）的真机截图需要**当次检索真的命中结果**，
   而补截图期间本机 IP 正被搜索引擎风控（详见 `检索层风控与加固_2026-09-21.md` 加固 6，
