为什么做

便民就医的三类真痛点

信息分散

同一类资源（如抗蛇毒血清）散在新闻、政府公开栏、医院官网，用户要翻多个站才能拼出"哪家有"。

信息过期

易变资源（血清库存、出诊排班）时效性强，旧报道当"现在有"会误事——这是医疗场景最危险的坑。

难核验

回答不标来源，用户无法判断"这话说的是哪家、哪天、可靠吗"，信任建立不起来。

混淆风险

同名医院多院区、不同来源说法冲突，混在一起答会直接误导就医决策。

讲稿：不要念卡片，用「抗蛇毒血清」一个例子串起来——被蛇咬了的人最怕的是"搜到的说有、跑到却没有"。我们的产品就是冲着这四类痛点去的。强调：过期与混淆是医疗场景的"高危区"，也是医疗场景里最需要交代清楚的一点。
我们怎么做

真联网检索 + 4 段式诚实结构化输出

  • 真联网：编排层把用户问题转成检索式，真实调用搜索引擎（so360 / mso360 / sogou 三同族瀑布回退 + 神马独立源），不是预置答案。
  • 4 段式契约：①查询条件 ②查询结果 ③信息依据 ④使用提示——结构固定、字段完备、来源必填。
  • 诚实三态：每条资源标「历史上有相关报道 / 公开页面介绍具备相关能力 / 目前是否可提供尚待核实」，把"不确定"显式说出来。
  • 零编造：查不到就明说"未查到"，绝不补一个看似合理的假结果；无密钥时走 need_key 降级而非编造。
讲稿：核心是"4 段式"——它既是给用户的阅读结构，也是给系统的校验契约。强调"零编造"：很多医疗助手失误在"答得像个专家但查无此据"，我们用结构性护栏从根上堵死（见下一页）。
核心差异化 ①

诚实护栏 R1–R13：把"不骗人"写进架构

R1–R3 边界 / 拒答 / 紧急提示

非医疗域礼貌拒绝；涉诊断开药等越界请求不答；命中毒蛇咬伤等紧急情况先给急救提示。

R4–R6 来源必填 / 禁断言 / 诚实标注

每条结果必须有可核验来源 URL；不替代医生做诊断断言；无结果如实标注。

R7–R9 易变资源三态 / 院区纪律

抗蛇毒血清等易变资源强制三态标注；不同院区地址/科室/排班不得混用。

R10–R12 院区 / 同名消歧 / 冲突提示

同名多家逐条标院区；多来源冲突主动提示"以官方为准"。

讲稿：这是我们的"最核心的架构设计"。上一届的已知问题是"硬编码冒充查询"，我们用 R1–R13 结构性校验（字段完备/来源必填/边界拒答/紧急提示/禁断言/诚实标注/检索真实性/院区纪律/同名消歧/冲突提示）从架构级堵死。演示时可点开"护栏留痕"看打回轮数，证明真在跑。
核心差异化 ②

超出基础的进阶能力展示

A2 同名医院 / 院区自动消歧

多后端返回同名多家时，逐条标注所属院区与地址，不混用（与 R10 呼应）。

A3 多来源冲突自动提示

同一事实不同来源说法不一致时，主动高亮"来源间存在冲突，以官方为准"。

A4 横向比较视图

结果页"对比视图"把多家医院同资源并排比；表格列完全由数据动态生成，不硬编码距离/坐标。

B1 历史记录 / B2 条件筛选

可回看过往会话；结果按类型动态筛选 + 名称/说明搜索，降低信息过载。

讲稿：基础要求均已覆盖，差异体现在进阶项。重点讲 A2/A3：同名消歧与冲突提示是"真联网多源"才暴露的真实问题，静态数据的 Demo 遇不到。这恰好说明系统确实在跑多后端真实检索。
技术架构

编排层 + 护栏层 + 多后端检索（抗限流独立性）

  • 编排层：把问题→检索式→生成→护栏打回的循环跑通，含流式进度与反射重试。
  • 护栏层：R1–R13 作为生成后结构性校验，不合格打回重组织，判据来自字段不来自词表。
  • 检索独立性：so360/mso360/sogou 同族瀑布回退，叠加神马（m.sm.cn）独立源——独立限流桶，避免"同族一起被风控"的伪冗余。
  • 密钥零落盘：用户模型密钥走外部密钥箱，源码发货不含任何密钥值；无密钥走诚实降级。
讲稿：讲"独立性"——这是稳定性关键。三个 360 同族后端一旦 IP 被风控会一起挂，等于没备份；神马是阿里/UC 独立运营的不同限流桶，实测为本机真实可达的独立源。一句话：我们为"生产级稳定"专门加了独立源。

商业交付能力

谁采购 · 怎么部署 · 成本结构 · 场景契合

采购方

地市级卫健委 / 便民服务平台 / 医院导诊台 / 县域医共体——把"查资源"能力嵌进现有便民入口。

部署路径

一键启动包（容器化），接入方自带模型密钥即可，源码不含密钥；可私有化部署在政务内网。

成本结构

检索免密钥（公开源）；仅模型调用按量计费；无爬虫运维成本。边际成本随调用量线性、可控。

场景契合

与"便民就医"赛题高度契合：解决信息分散/过期/难核验，且不替代医生诊断，合规边界清晰。

讲稿：商业交付是本届薄弱维度，我们专门补了《商业交付与落地说明》。讲清"采购方不是个人用户，是平台方"，部署是"接入口+自带密钥"，成本是"检索免费、模型按量"。一句话：能落地、能算账。
路演演示动线

4 分钟现场跑一遍（建议顺序）

  • ① 问「昆明哪家医院有抗蛇毒血清？」→ 看真实检索过程留痕 + 三态诚实标注。
  • ② 点「对比视图」→ 多家医院并排比，来源可点。
  • ③ 问一个多来源冲突的点 → 看 A3 冲突高亮"以官方为准"。
  • ④ 问一个歧义问题（如"帮我找专家"缺科室）→ 看澄清轮不检索、追问字段。
  • ⑤ 点「历史记录」→ 回看刚才的会话，证明多轮承接。
讲稿：演示顺序就是"真联网→诚实→进阶→澄清→历史"一条线，和 Deck 主线一一对应。关键：让演示对象亲眼看到"检索过程"和"护栏留痕"在动，而不是看静态结果。卡在澄清轮那一步最能证明"字段驱动、不硬编码台词"。
设计取舍与边界

我们的诚实边界，就是我们的最核心的架构设计

  • 真联网 + 零编造：查不到就说查不到，不拿"像真的"骗用户——医疗场景这是底线，也是用户最在意的。
  • 架构级诚实：R1–R13 把"不骗人"写进校验，不是靠提示词祈祷。
  • 抗限流独立性：神马独立源让"真联网"在生产环境真稳。
  • 诚实标注风险：本机 IP 风控下的真机截图仍在补拍（代码零改动），我们不把降级页当可用源——这本身就是诚实纪律的延伸。
讲稿：收尾回到主线：别人拼"答得像"，我们拼"答得真"。最后一句收在这里——「便民就医，最贵的不是功能，是信任；我们把信任做进了架构。」（真机截图那项是唯一待补，诚实说明，不遮掩。）
