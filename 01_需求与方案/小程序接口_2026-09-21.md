# 小程序接口说明（OPC接单吧第三届 · AI 医院资源查询与便民就医助手）

> 目的：把「Web 页面」与「小程序」统一到**同一套 HTTP 契约**上。
> 开发指导架构（`开发指导架构_2026-09-21.md`）里 M6 的完成标准是
> 「小程序接口可用 curl / 测试页模拟」——本文档即该标准的落地件。
> 生成时间：2026-09-21。所有示例均为**本机实测输出**（非示意）。

---

## 1. 接口清单

| 方法 | 路径 | 用途 | 谁在用 |
|---|---|---|---|
| POST | `/chat` | **主接口**：一次请求 → 一个 4 段式信封 | 小程序（wx.request）/ curl / Web |
| POST | `/chat/stream` | 同上，SSE 分阶段推进度（检索中/命中数/护栏打回） | **仅 Web 调试**（小程序不便消费 SSE） |
| POST | `/reset` | 重置会话（清空服务端上下文） | Web「重置会话」按钮 |
| GET | `/health` | 状态探测（密钥/连接/搜索后端/运行保障用量） | 运维、评委自查 |
| GET | `/api/keys/providers` | 预设模型供应商清单（13 家，**不含密钥**） | 「添加密钥」弹窗 |
| GET | `/api/keys/status` | 当前是否已配置密钥（自动扫描项目外密钥库） | 「添加密钥」横幅 |
| POST | `/api/keys/add` | 提交并即时校验密钥，成功则写入项目外密钥库 | 「添加密钥」弹窗 |
| GET | `/` | Web 交互界面 | 人 |
| GET | `/static/小程序接口测试.html` | **小程序接口模拟测试页** | 评委/开发者 |

## 2. `/chat` 请求契约

```json
{
  "message": "昆明哪家医院有抗蛇毒血清？",
  "session_id": null
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `message` | string | 是 | 用户提问；后端会清洗（去控制符）并限长（默认 500 字） |
| `session_id` | string \| null | 否 | 首次传 `null`，后端返回新 id；**多轮对话把上次返回的 id 回传**即可继承上下文 |

**多轮用法（关键）**：把上一次响应的 `session_id` 原样回传；要开新对话就传 `null` 或调 `/reset`。

## 3. `/chat` 响应契约（ResponseEnvelope）

**无论成功失败，HTTP 状态码恒为 200**，成败看 `ok` 字段——这是为了让小程序/前端只写一套解析逻辑。

```json
{
  "ok": true,
  "session_id": "s_44964a44955f48be",
  "error_code": null,
  "output": { "…4 段式，见下…" },
  "retrieval_log": [
    { "action": "search", "query": "昆明市第一人民医院 急诊电话", "city": "昆明",
      "status": "ok", "hit_count": 5, "timestamp": "2026-09-21T14:42:32" }
  ],
  "reflection_count": 0,
  "degraded": false,
  "mode": "agent",
  "note": "ok"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | bool | 业务层成败 |
| `session_id` | string | 会话标识（下次回传） |
| `error_code` | string \| null | 失败码，见 §6 |
| `output` | object | **答案永远在这里**（4 段式） |
| `retrieval_log` | array | 检索/护栏过程留痕（**"可核验"的抓手**，可选择性展示给用户） |
| `reflection_count` | int | 护栏打回轮数（>0 表示护栏真的介入过） |
| `degraded` | bool | 是否降级交付（护栏超限 / 检索失败 / 限额） |
| `mode` | string | `agent`（医疗域正常）/ `chat`（闲聊寒暄）/ `need_key`（未配密钥） |
| `note` | string | 附加说明（如降级原因） |

### 3.1 `output`（4 段式）

| 段 | 字段 | 类型 | 说明 |
|---|---|---|---|
| ① 查询条件 | `query_condition` | object \| null | `{region, hospital, department, resource, title, date}`；`mode=chat` 时为 `null` |
| ② 查询结果 | `query_results` | array | 见下 |
| ③ 信息依据 | `info_basis` | array | `{title, url, note, source_type}`，`source_type` ∈ `权威`/`补充` |
| ④ 使用提示 | `usage_tips` | string[] | 安全提示、时效提示；`mode=chat` 时这里装的就是闲聊回复正文 |

`query_results[]` 单项：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 医院/科室/医生/资源名称 |
| `type` | string | 医院/科室/医生/资源/其他 |
| `description` | string | 说明（忠实来源，不编造） |
| `info_status` | string \| null | **信息状态三态**（易变资源必填，见下） |
| `source` | object | **必填**：`{title, url, source_type, updated_note}` |

### 3.2 信息状态三态（核心真实性字段）

| 取值 | 含义 | 小程序展示建议 |
|---|---|---|
| `历史上有相关报道` | 只有往期报道，不代表当前 | 灰色 + "历史信息"角标 |
| `公开页面介绍具备相关能力` | 官方/公开页面表明具备该能力 | 青色 + "页面介绍"角标 |
| `目前是否可提供尚待核实` | 随时间变化，需向医院核实 | **橙色警示** + "请电话核实"角标 |

> 例：抗蛇毒血清这类易变资源，护栏 **R9** 会强制要求标注三态，
> 避免用户把「2010 年的旧报道」误当成「今天确定能打」。

## 5. 小程序接入样例（wx.request）

```js
// 微信小程序：发起一次问诊查询
wx.request({
  url: 'http://127.0.0.1:8137/chat',   // 真机/上线须换 https 域名（见 §7）
  method: 'POST',
  header: { 'content-type': 'application/json' },
  data: { message: '昆明哪家医院有抗蛇毒血清？', session_id: app.globalData.sid || null },
  success: (res) => {
    const env = res.data;                 // ResponseEnvelope
    app.globalData.sid = env.session_id;  // 记住会话 → 实现多轮
    if (env.ok === false) {
      wx.showToast({ title: (env.output.usage_tips || ['请求未成功'])[0], icon: 'none' });
      return;
    }
    const out = env.output;               // 4 段式
    // ① 查询条件：out.query_condition
    // ② 查询结果：out.query_results[]（name/type/description/info_status/source）
    // ③ 信息依据：out.info_basis[]
    // ④ 使用提示：out.usage_tips[]
    // 检索留痕：env.retrieval_log[]（可核验用，可不展示）
    wx.setStorageSync('lastAnswer', out);
  },
  fail: () => wx.showToast({ title: '网络异常', icon: 'none' })
});
```

**模拟测试页**：浏览器打开 `http://127.0.0.1:8137/static/小程序接口测试.html`，
可编辑请求 JSON、一键发送 `/chat` 或 `/chat/stream`，并看到原始响应、字段提取表与事件流。

## 6. 错误码表（`ok=false` 时看 `error_code`）

| error_code | 触发场景 | `output.usage_tips` 会给什么 |
|---|---|---|
| `EMPTY_MESSAGE` / `TOO_LONG` / `INVALID_INPUT` | 空输入 / 超长 / 危险协议 | 具体原因说明 |
| `RATE_LIMIT` | 网关级限流（默认 300 次/分） | "请求过于频繁，请稍后再试。" |
| `LLM_RATE_LIMIT` | 模型调用限速（默认 30 次/分，运行保障） | "模型调用过于频繁…" |
| `LLM_BUDGET_EXCEEDED` | 当日 token 预算用尽 | "今日模型额度已用尽…" |
| `NEED_KEY` | 未配置模型密钥（`mode=need_key`） | "尚未配置模型密钥，请点「添加密钥」后重试。" |
| `NO_MODEL` | 密钥已配但未选模型 | 提示在「添加密钥」处选择模型 |
| `UPSTREAM_ERROR` | 模型网关异常 | 上游错误摘要 |
| `INTERNAL` | 未捕获异常（兜底） | "服务暂不可用，请稍后重试。" |

> 注意：`LLM_BUDGET_EXCEEDED` / `LLM_RATE_LIMIT` 属**运行保障**（赛题进阶3），
> 是"主动刹车"，不是故障；`/health` 的 `usage` 字段可看实时用量。

## 7. 部署注意（小程序特有）

1. **HTTPS**：微信小程序正式环境**只允许 https**。本机 `http://127.0.0.1:8137` 仅用于开发者工具调试（可勾选"不校验合法域名"）。
2. **域名白名单**：上线需把接口域名加入小程序的「request 合法域名」并在微信后台备案。
3. **CORS**：后端已开 CORS 白名单（默认 `127.0.0.1` / `localhost` 的 5173、8137 端口），
   可用环境变量 `OPC_CORS_ORIGINS` 覆盖（逗号分隔）；`prod` 环境禁用 `*`。
4. **超时**：一轮问答含"联网检索 + 模型生成"，实测约 5~20 秒；
   小程序 `wx.request` 默认超时 60 秒，通常够用；若网络慢可调大。
5. **会话保持**：服务端会话为**进程内内存**（重启即清空）。单机演示足够；
   若需多实例/持久化，把 `src/session.py` 换成 Redis 实现即可（接口不变）。

## 8. 诚实标注的局限

1. `/chat/stream`（SSE）**只适合浏览器**；小程序统一用 `/chat`（因为 SSE 在小程序端消费不便）。
2. 检索来自**免密钥公开检索**（360 搜索桌面版优先，移动版与搜狗回退），
   返回的是**公开网页信息**，非医院实时系统数据；因此"是否可提供"必须标三态并向医院核实。
3. 会话为进程内内存，多实例部署需外置存储（见 §7.5）。
