## 一、文档定位

本文是本项目的完整部署参考，说明在本地或容器环境中运行本作品所需的全部步骤、配置项、验证方式与已知限制。

### 3.3 启动服务

双击 `启动项目.bat`。启动器按顺序完成以下工作，全过程输出中文进度提示：

1. 在项目目录内创建独立的 Python 虚拟环境（`.venv/`），不影响本机原有 Python 环境；
2. **优先从 `wheels/` 离线安装依赖**（无需联网）；离线包异常时自动回退在线安装；
3. 启动后端服务并等待健康检查通过；
4. 自动打开浏览器指向交互界面。

出现下列输出即表示启动成功：

```
  ✔ Python 就绪
  ✔ 依赖就绪
  ✔ 后端已启动
  · 打开浏览器：http://127.0.0.1:8137/
```

> 服务默认只监听 **127.0.0.1**（本机回环地址），同一局域网内的其他设备无法访问。这是刻意的安全默认值，如需变更请参见 §3.6。

### 3.4 配置模型密钥

模型密钥入口位于页面**右上角**，为常驻可见状态：

| 状态 | 界面表现 |
|---|---|
| 未配置 | 琥珀色呼吸闪烁：`● 未配置模型密钥 · 点此添加` |
| 已配置 | 绿色常亮：`● DeepSeek · 更换密钥`（显示实际使用的服务商名称） |

**首次打开页面时会自动弹出操作引导**，直接指出入口位置。按以下三步完成配置：

1. 在「模型供应商」下拉框中选择服务商（已内置主流国内厂商预设）；
2. 粘贴对应的 API Key（模型调用凭据）；
3. 点击「连接并保存」，系统会立即校验连接可用性。

保存后入口变为绿色常亮，此后可随时点击更换。

**密钥存储位置**：`%USERPROFILE%\.opc_health\keys.json`，即 `C:\Users\<用户名>\.opc_health\keys.json`，位于**项目目录之外**。

该设计的目的：密钥不会写入项目文件夹，因此不会被误提交至版本库，也不会被打入任何交付包。交付包另有独立的泄漏自检环节（见 §八）。

> **界面措辞说明**：界面显示「已配置」而非「已连接」。后端只做密钥的**存在性校验**，无法代表服务商侧此刻仍然有效（密钥可能在配置后被作废或额度耗尽）。实际失效时，对话链路会返回结构化错误，不会虚报状态。

### 3.5 提问与查看结果

在输入框中输入问题，例如：

- `昆明哪家医院有抗蛇毒血清？`
- `云南省第一人民医院心血管内科怎么样？`
- `小孩发烧 39 度，该挂哪个科？`（触发紧急就医提示）

界面上方会出现**检索进度时间线**（形如「正在联网检索… → 命中 5 条 → 结构校验通过」），随后在下方渲染四段式结果。**回答产出后，时间线自动收拢为一行摘要**（形如「过程已收拢 · 5 步 · 命中 5 条」），点击可重新展开复核全过程。

关闭服务的方式：直接关闭启动器所在的命令行窗口，或在窗口内按 `Ctrl + C`。

### 3.6 可调整的运行参数

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `OPC_PORT` | `8137` | 服务监听端口；端口被占用时启动器会自动顺延至下一空闲端口并在提示中告知实际端口 |
| `OPC_HOST` | `127.0.0.1` | 监听地址；**改为 `0.0.0.0` 会使服务暴露到局域网，请谨慎评估** |
| `OPC_API_TOKEN` | 空 | 可选网关令牌；设置后，敏感端点（添加密钥 / 重置会话 / 历史记录）需携带令牌方可调用 |
| `OPC_SEARCH_BACKENDS` | `so360,mso360,sogou,sm` | 检索后端顺序 |
| `OPC_SEARCH_BUDGET_SECONDS` | `18` | 单次检索外呼总耗时上限（秒） |
| `OPC_LLM_RATE_LIMIT_PER_MIN` | `30` | 每分钟模型调用上限 |

## 四、路径 B：容器部署

适用于具备容器环境的标准化部署场景。

```bash
cd 02_源码/deploy
docker compose up -d
```

启动后访问 `http://localhost:8137/`。

容器内没有用户目录，因此无法使用项目外的密钥库，模型密钥改由环境变量提供：

| 场景 | 配置方式 |
|---|---|
| 需要模型能力 | 复制 `deploy/.env.example` 为 `deploy/.env`，填入 `OPC_LLM_API_KEY` / `OPC_LLM_BASE_URL` / `OPC_LLM_MODEL`，再执行 `docker compose up -d` |
| 仅查看界面 | 无需填写任何变量，直接执行 `docker compose up -d`。服务进入**待配置模式**：页面与接口正常响应，但不发起检索、不调用模型，直接给出配置引导 |

> **检索环节不需要任何密钥。** 本作品的检索层使用公开搜索页面，默认后端为 `so360`（360 搜索桌面版）→ `mso360`（360 搜索移动版）→ `sogou`（搜狗）→ `sm`（神马搜索），无需申请任何搜索接口。

## 六、接口与接入

### 6.1 主要端点

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/health` | 健康检查：返回密钥状态、检索后端、实时用量 |
| `POST` | `/chat` | 一次性问答：返回完整四段式结果 |
| `POST` | `/chat/stream` | 流式问答（SSE，Server-Sent Events 服务器推送事件）：逐步推送检索进度，便于展示「正在检索」状态 |
| `POST` | `/reset` | 清空指定会话的多轮上下文 |

请求示例：

```bash
curl -X POST http://127.0.0.1:8137/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"昆明哪家医院有抗蛇毒血清？","session_id":"demo-001"}'
```

完整接口契约（字段定义、错误码表、微信小程序 `wx.request` 调用样例）见 `01_需求与方案/小程序接口_2026-09-21.md`。

项目内附有**接口自测页**，可在浏览器中修改请求参数并查看原始返回：`http://127.0.0.1:8137/static/小程序接口测试.html`。

### 6.2 小程序接入注意事项

| 事项 | 说明 |
|---|---|
| 传输协议 | 微信小程序正式环境仅允许 HTTPS；本地 `http://127.0.0.1` 仅在开发者工具中关闭域名校验后可用于调试 |
| 域名白名单 | 部署到公网后，需在小程序后台将域名加入「request 合法域名」 |
| 跨域配置 | 服务端已内置白名单机制；正式部署时通过 `OPC_CORS_ORIGINS` 配置，**不应使用 `*`** |
| 超时设置 | 检索与生成通常耗时 5~15 秒，建议客户端超时设为 30 秒以上；或直接使用流式接口以避免长时间无反馈 |

## 七、未配置模型密钥时的系统行为

未配置模型密钥时，系统进入**待配置模式**：接口与页面正常响应，直接返回「未配置模型密钥」引导（`error_code = NEED_KEY`），**不发起检索、不调用模型、不生成任何替代性答案**。

关键路径的行为对照如下：

| 状态 | 行为 |
|---|---|
| 未配置模型密钥 | 待配置模式：返回配置引导，不检索、不调模型、不伪造答案 |
| 已配置密钥但检索失败 | 返回「暂未检索到可核验的公开信息」并说明失败原因；`query_results` 与 `info_basis` 均为空，不编造内容 |
| 检索成功 | 结果逐条标注来源与链接，可点击核验；对易变资源（如抗蛇毒血清库存）强制标注信息状态 |

相关取证见 `03_测试记录/真实性证据_2026-09-21.md`。

## 八、交付包生成与自检

交付包由项目根目录的 `打包交付.py` 生成，脚本内置三项校验：

| 校验项 | 规则 |
|---|---|
| 关键文件齐全 | 逐一核对入口、源码、前端、测试与文档清单，缺一即报错 |
| 离线依赖完整 | 统计 `wheels/` 内轮子数量，为 0 即报错 |
| 密钥零泄漏 | 排除 `.env` / `keys.json` / `*.local.json`，并按文件名关键词（`密钥` / `secret` / `token` / `apikey` 等）做二次拦截 |

重新生成交付包：

```bash
python 打包交付.py
```

产物输出至 `04_交付物/OPC接单吧第三届_交付包_YYYYMMDD.zip`，返回码 `0` 表示三项校验全部通过。

生成后建议执行一次**独立复验**（不复用打包脚本的自报结果，直接读取 ZIP 字节重新校验）：

```bash
python 复验交付包.py
```

复验内容包括：包内条目数与 CRC 完整性、敏感文件黑名单、字节级密钥扫描（从项目外密钥库装载真实密钥进行比对）、离线依赖数量，以及包内每个 `.py` 文件的语法可编译性。返回码 `0` 表示通过。

## 十、常见问题

| 现象 | 原因 | 处理方式 |
|---|---|---|
| 双击 `启动项目.bat` 后窗口一闪而过 | 未安装 Python，或安装时未勾选 `Add to PATH` | 重装 Python 并勾选该项；或改走路径 C 查看报错 |
| 提示「未检测到 Python 3.10+」 | Python 版本过低或未配置到 PATH | 安装 3.10 以上版本 |
| 依赖安装失败 | 离线轮子与当前 Python 版本不匹配（如使用 3.14 或 32 位 Python） | 启动器会自动回退在线安装；仍失败时建议改用 Python 3.11 或 3.12（64 位） |
| 提示端口被占用 | 默认端口 8137 已被其他程序占用 | 关闭占用程序，或先执行 `set OPC_PORT=9000` 再启动 |
| 浏览器未自动打开 | 默认浏览器被系统策略拦截 | 手动访问提示中给出的地址（默认 `http://127.0.0.1:8137/`） |
| 页面右上角显示「未配置模型密钥」 | 首次进入的正常状态 | 点击该入口完成配置 |
| 已配置密钥但回答没有结果 | 网络不通，或搜索引擎临时限流 | 系统在此情形下不生成替代性答案；检查网络后重试 |
| 连续快速提问后被限速 | 每分钟模型调用上限保护 | 等待一分钟；阈值可通过 `OPC_LLM_RATE_LIMIT_PER_MIN` 调整 |

## 十二、检索来源与限流处理

本作品的检索层使用**免密钥**的公开搜索引擎页面。在短时间高频请求下，搜索引擎可能触发风控，返回「HTTP 200 但内容为安全验证页」的响应。系统对此做如下处理：

1. 检索层统一**识别风控页**并判定该后端失败，避免将验证页当作结果解析、进而产出编造的来源；
2. 按配置顺序自动切换至下一后端；同时提供 10 分钟结果缓存与不小于 1 秒的出站节流；
3. 全部后端不可用时，返回「暂未查到可核验的公开信息」，并附上可点击的手动检索入口；
4. 360 搜索的桌面版与移动版为同一引擎的两个不同入口，实测桌面版返回验证页时移动版仍可正常返回结果，因此二者互为冗余。**该机制提高的是取数成功率，不等同于不受限流影响**——在持续高频请求下，两个入口会先后被风控。

正常使用（单次会话提出若干问题）不会触发限流。完整取证见 `03_测试记录/检索层风控与加固_2026-09-21.md`。
