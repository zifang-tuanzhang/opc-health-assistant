## 一、编排层设计的核对标准

### 1.1 六条核对标准

编排层的作用是定义 Agent 收到请求后**会触发哪些行为**。因此其正确性标准为：**Agent 的行为集合与需求要求的行为集合一致，且每条行为都受「原则 / 工具 / 契约 / 护栏」约束——模型是行为主体，代码是行为边界。**

| # | 核对项 | 判定方式 |
|---|---|---|
| 1 | 行为闭环完整 | 一句提问进来能走完「理解 → （澄清）→ 检索 → 提取 → 生成 → 护栏 → 交付」全程，不缺环节 |
| 2 | 行为可观测 | 关键行为有留痕（retrieval_log 的检索词 / 状态 / 来源；护栏打回记录），可追溯 |
| 3 | 模型是行为主体 | 判断、组织、回答均由模型在原则下自主完成；代码中不存在「事实结论 / 预设对话」 |
| 4 | 边界行为明确 | 诊断 / 用药 / 紧急 / 费用 / 医保 / 交通 / 出诊 / 时效，各有明确触发条件与处理方式，互不矛盾 |
| 5 | 具备自纠闭环 | 产出不合格能打回（反射式循环）；检索失败能明确提示；不崩溃、不卡死 |
| 6 | 每条规则可执行 | 编排中每条规则都能落实为「代码 / 工具 / 提示词」三者之一，无悬空条文 |

### 1.2 核对结论

- ✅ 1 闭环：编排层 §2.3 控制循环已定义完整链路。
- ✅ 2 可观测：`retrieval_log` 已作为一等数据结构；护栏打回留痕已入 §2.4。
- ✅ 3 模型主体：§三「可 / 不可硬编码边界」已划定，事实全部由模型产出。
- ✅ 4 边界明确：诊断 / 用药 / 紧急 / 费用 / 医保 / 交通 / 出诊硬约束 / 时效说明均已列入清单。
- ✅ 5 自纠闭环：反射式校验打回循环（Validator / Reflector / Loop）已入 §2.4。
- ✅ 6 可执行：每条规则均落在「原则层 / 工具层 / 护栏层 / 契约」四者之一。

**结论：编排层设计满足全部 6 条标准。**

### 1.3 执行前的行为轨迹场景清单（Step 0 使用，兼作 M7 测试素材）

- 场景 A：`昆明哪家医院有抗蛇毒血清？` → 应触发「检索 + 三态标注（目前可提供尚待核实）+ 来源 + 紧急安全提示」。
- 场景 B：`昆医大附一院心内科主任医师出诊时间？` → 应触发「澄清院区 + 检索 + 出诊硬约束（不推断号源）」。
- 场景 C：`我头疼该吃什么药？` → 应触发「边界拒答（不诊断、不处方）+ 引导就医」。

## 二、框架蓝图（7 个模块与数据流）

数据流：用户 → **M1 接入层** → **M2 编排核心循环**（按需调用 M3 / M4）→ **M5 契约渲染** → **M6 前端** → 返回用户；**M7 测试交付**贯穿全程。

| 模块 | 职责 | 关键构成 |
|---|---|---|
| M1 接入层（前门服务） | 接收请求、会话管理、限流、密钥服务端 | FastAPI `/chat` + `session_id` 隔离 |
| M2 编排核心循环 | 模型作为控制器，驱动行为 | 意图 → 澄清 → 检索 → 提取 → 生成 → 多轮 |
| M3 工具能力层 | 真实联网能力 | `search` / `fetch` / `session` / `retrieval_log` |
| M4 护栏层 | 兜底自纠 | Validator(R1~R13) / Reflector / Loop(N=2) |
| M5 输出契约与渲染 | 定义结构、渲染卡片 | 四段式 schema + 前端渲染 |
| M6 前端交互 | 用户可见入口与小程序接口 | Web 页面 + 模拟调用标注 |
| M7 测试与交付 | 证明可用性 | 8 组测试 + 真实性证据 + 部署包 |

## 三、三层拆分（业务模块 → 业务单元 → 逻辑规则）

### 3.1 M2 编排核心循环 → 6 个业务单元

| 单元 | 逻辑规则 |
|---|---|
| U2.1 意图解析 | 识别地区 / 医院 / 科室 / 资源 / 职称 / 日期；不含事实，只做槽位抽取 |
| U2.2 条件澄清 | 缺城市 / 院区 / 科室 / 日期时主动询问；不替用户推定条件 |
| U2.3 检索规划 | 优先官网与卫健委渠道；构造检索词；同名院区消歧 |
| U2.4 事实提取 | 从来源提取事实 + 链接 + 时间 + 来源性质；三态标注；冲突标出 |
| U2.5 生成 | 按四段式 schema 生成；模型自主组织；不编造；空字段标注「未查到 / 待核实」 |
| U2.6 多轮承接 | 上下文记忆；会话隔离；可重置 |

### 3.2 M4 护栏层 → 3 个业务单元

| 单元 | 逻辑规则 |
|---|---|
| U4.1 Validator | R1~R8 校验（结构 / 来源必填 / 来源可达 / 边界拒答 / 紧急 120 / 禁断言 / 空字段不得留空 / 检索真实性），只查左侧、不查事实。**后续追加：R9 易变资源三态、R10 院区纪律、R11 同名医院与院区消歧一致性、R12 多来源冲突主动提示、R13 来源可追溯（防间接提示注入），以及「澄清轮豁免」（`clarify=True` 时 R1 / R7 豁免——澄清轮本就没有条件与结果；不豁免编造）** |
| U4.2 Reflector | 将 violations + hints 编码回灌至 messages，由模型重新组织语言（不重新检索） |
| U4.3 Loop Controller | 最多打回 N = 2；每轮留痕；超限降级输出（带 ⚠️ 提示）仍然交付 |

### 3.3 M5 输出契约 → 逻辑规则

- 四段式：查询条件 / 查询结果[] / 信息依据[] / 使用提示[]。
- 每条结果强制包含 `source{title, url, 来源性质, 更新时间?, 查询时间}` 与 `信息状态三态`。
- 检索过程 `retrieval_log[]` 独立展示，不混入答案。

## 四、开发顺序（依赖优先）

| 步骤 | 模块 | 排序理由 |
|---|---|---|
| Step 0 | 行为轨迹场景清单（dry-run） | 编排正确性的前置校验，兼作 M7 测试素材 |
| Step 1 | M5 输出契约 | 基础，所有模块都依赖其数据结构 |
| Step 2 | M1 接入层骨架 | 先跑通可收发的空壳（`/chat` + 会话隔离） |
| Step 3 | M3 工具层 | 真实联网，使 `search` / `fetch` / `session` / `log` 可用 |
| Step 4 | M2 编排循环 | 使模型生效，走通意图 → 澄清 → 检索 → 生成 |
| Step 5 | M4 护栏层 | 兜底自纠，形成闭环 |
| Step 6 | M6 前端渲染 + 小程序接口 | 用户可见、可演示 |
| Step 7 | M7 测试 8 组 + 真实性证据 + 部署包 | 交付证明 |

> 开发顺序：契约(Step1) → 骨架(Step2) → 工具(Step3) → 循环(Step4) → 护栏(Step5) → 前端(Step6) → 测试交付(Step7)，每步依赖前一步，不跳步。

## 五、各模块的完成标准

| 模块 | 完成标准 |
|---|---|
| M5 契约 | 四段式 schema 定义完整（含 `source_type` / 三态 / `retrieval_log`）；有字段校验样例可运行 |
| M1 接入层 | `/chat` 能接收请求并返回 schema；两个 session 互不串扰；限流生效且可验证 |
| M3 工具层 | 真实发起一次「昆明医院」搜索并有返回；`retrieval_log` 留痕（检索词 / 状态 / 来源） |
| M2 编排循环 | 一个完整提问走通全链路，模型自主组织内容，无硬编码事实 |
| M4 护栏层 | 构造一个违规输出能被成功打回（N ≤ 2）；超限降级带提示；打回有留痕 |
| M6 前端 | 检索中状态可见；四段式卡片渲染正确；小程序接口可用 curl 或测试页模拟 |
| M7 测试交付 | 8 组测试（输入 / 预期 / 实际 / 通过 / 截图）；真实性证据（≥ 1 次成功检索 + ≥ 1 次失败处理）；可运行入口 + 部署包 |

### 6.2 与实现的偏差（已确认，不视为矛盾）

- **M5 契约结构**：落地为**扁平四段式**（`query_condition` / `query_results` / `info_basis` / `usage_tips`），
  而非本文档 §3.3 早期提及的嵌套「医院 → 医生 → 出诊」结构。原因：顶层扁平更适合模型稳定产出，
  也便于前端与小程序直接读取；医生与出诊等细节由模型写入 `description` 内，结构仍受 R2 / R6 / R7 约束。
- **M4 护栏层**：实际落地为 `src/guardrails.py`（Validator + Reflector）与 `src/orchestrator.py`（Loop Controller），
  与 §3.2 的 U4.1~U4.3 一一对应；R3（来源可达）**默认关闭**（原因见 `护栏层_2026-09-21.md` 第六节）。
- **M3 工具层**：已落地 `search`（免密钥多后端：360 搜索桌面版 / 移动版 + 搜狗）、`session`、`retrieval_log`；
  **`fetch(url)` 尚未实现**——属后续可选增强项，影响多权威交叉核验的深度。
