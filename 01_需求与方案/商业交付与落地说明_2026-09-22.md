## 〇、一句话定位

一个**不依赖任何付费接口、评审只需自带 1 个模型密钥即可跑起来**的"便民就医资源查询助手"：真联网检索公立医院与可核验民营医院的科室、医生、号源、院区资源，**每条结论都带可点击的真实来源链接、且检索不到时诚实说"没查到"、绝不编造**。

> 这条"真联网 + 诚实护栏 + 零编造"的主线，正是上一届"硬编码冒充查询"已知问题的**架构级反面**——本届从代码层把冒充查询堵死了。

## 一、谁会采购 / 用在哪（目标用户与落地场景）

| 角色 | 为什么需要 | 我们的契合点 |
|---|---|---|
| **地方卫健部门 / 政务服务平台** | 便民就医是政务服务高频场景，需要"权威入口 + 可追溯来源" | 来源全部是可点击的真实公开链接，不编不猜，符合政务"可核验"要求 |
| **医院宣传科 / 门诊办** | 把本院科室、专家、出诊、院区信息集中到一个对话入口，减轻热线压力 | 多后端检索天然覆盖本院官网、挂号平台等公开信息；院区纪律（R10）保证不同院区不混用 |
| **县域 / 基层医疗联合体** | 基层群众不清楚"去哪看、找谁看"，需要对话式导诊 | 支持多轮补充条件（地区/院区/科室/日期），承接上一轮继续查 |
| **便民小程序 / 公众号运营方** | 在已有流量入口里挂一个"就医助手"能力 | `POST /chat` 接口可被小程序服务端直接调用（详见第五节），无需改前端 |

**诚实边界（必须写清，不夸大）**：演示范围选**昆明市**（赛题允许"选一个城市作为主要演示范围"），**架构本身支持任意城市**——换城市只需改一个环境变量 `OPC_DEMO_CITY`，不绑死任何本地数据。我们不声称"已覆盖全国所有医院"，只声称"演示昆明、架构可泛化、来源以官方为准"。

## 二、怎么部署到真实便民平台（部署路径）

**核心卖点：零额外配置即可跑。**

| 步骤 | 动作 | 评审/采购方成本 |
|---|---|---|
| ① 拿包 | 解压交付 ZIP（内含 51 个离线依赖轮子，无需联网装依赖） | 0 |
| ② 启动 | 双击 `启动项目.bat`，自动开 `http://127.0.0.1:8137` | 0（实测全流程 **25.2 秒**，对赛题 15 分钟要求余量 97%） |
| ③ 配密钥 | 点右上角「模型密钥」入口 → 选一家厂商 → 粘贴**自己的**模型 Key | 1 个 Key（可选 13 家厂商之一） |
| ④ 上线 | 内网/政务云起一个服务进程，反向代理到域名即可对外 | 1 台普通服务器 |

- **不申请任何搜索接口**：检索走免密钥公开搜索页面（so360/mso360/sogou 三后端瀑布回退），采购方**无需再办搜索 API 账号、无需再付搜索费**。
- **密钥不落盘风险**：模型密钥存于项目目录之外的外部密钥库（`%USERPROFILE%\.opc_health\keys.json`），不进代码、不进仓库、不进日志；交付包内置泄漏自检 + 独立复验逐字节扫描（密钥硬命中 0）。
- **不填 Key 也能起**：进入"骨架模式"仍真实联网检索，只是不接大模型（页面明确提示未配置）——便于演示环境快速验证。

## 三、成本结构（诚实算账）

| 成本项 | 金额 | 说明 |
|---|---|---|
| 检索成本 | **0** | 免密钥公开检索，不调用任何付费搜索 API |
| 模型成本 | 按量计费 | 评审/采购方用**自己的**模型 Key，按厂商公开单价，与作品无关 |
| 部署成本 | 极低 | 单进程 + 静态页，1 台 2C4G 服务器即可；无数据库、无 Redis、无中间件 |
| 运维成本 | 低 | 进程内内存实现，重启即清空；无外部存储依赖，无备份负担 |
| 我们的交付 | 一次性 | 作品本身 + 文档 + 测试证据，无订阅费 |

> 这是"适合"路线：我们没有为了"看起来更全"去接付费搜索 API 或上向量数据库——那会**增加采购方的配置与费用门槛**，反而削弱"零配置上手"这个最大优势。

## 四、与便民就医场景的契合度

- **真需求**：群众问"哪家有卒中中心""某某医生周几出诊""去哪挂急诊"——都是高频、且必须可核验的问题。
- **我们的答法**：真联网检索 → 4 段式结构化输出（查询条件/查询结果/信息依据/使用提示）→ 每条带来源链接与日期 → 易变资源（血清/号源/床位）强制三态标注（"目前是否可提供尚待核实"）→ 院区纪律保证不同院区不混用。
- **安全底线**：诊断/用药意图（R4）明确拒答并引导就医；紧急症状（R5）优先提示 120；绝不编造"可预约成功""确定出诊"（R6）。
- **诚实兜底**：查不到时不断言"没有"，给官方渠道 + 可点击手动检索入口；评审连续多问偶发风控降级时，仍是"诚实告知 + 手动入口"，不编造。

## 五、接入路径（怎么挂到现有系统）

作品同时提供**网页入口**与**标准接口**，三种接入形态任选：

1. **独立网页**：直接部署 `index.html` 对话页，政务云/内网访问。
2. **嵌入小程序 / 公众号 / App（webview）**：把对话页用 webview（网页视图）嵌入现有便民应用，零改造。
3. **服务端调用接口**：现有小程序后端直接 `POST /chat`：

```json
// 请求
{ "message": "昆明哪家医院有抗蛇毒血清？", "session_id": "可选；首轮不传则返回新 id" }
// 响应
{
  "ok": true, "session_id": "s_xxx", "mode": "agent",
  "retrieval_log": [ { "action": "search", "query": "…", "status": "ok" } ],
  "output": { "query_condition": {}, "query_results": [], "info_basis": [], "usage_tips": [] },
  "error_code": null, "degraded": false
}
```

- 赛题要求"小程序实际集成"——明确**不作为所有选手强制要求**；我们用**明确标注"模拟调用"的接口测试页**验证接入流程，合法且省去真实平台授权负担。

## 六、已知限制（如实标注，不藏）

| 限制 | 说明 | 应对 |
|---|---|---|
| 演示范围 | 默认昆明，非全国 | 架构支持任意城市（`OPC_DEMO_CITY` 切换），不绑死本地数据 |
| 来源时效 | 公开页面会更新/删除，链接可能腐坏 | 检索层只认当前可访问真实链接；R3 可选探测可达性；结论以官方渠道为准 |
| 检索稳定性 | 免密钥后端受搜索引擎风控，极端高频会降级 | 三后端回退 + 总耗时预算（默认 18s）+ 诚实降级入口；可选加独立源进一步降概率 |
| 无外部存储 | 会话/缓存均为进程内内存 | 单实例演示足够；如需多实例共享，会话层接口已预留（文件/Redis 可替换） |
| 真实小程序集成 | 未做 | 赛题允许；以标注模拟页验证 |

## 七、为什么这条路"稳"

上一届我们栽在"硬编码冒充查询"——把预设答案当动态查询结果，被一眼识破、掉到末位。本届从架构上堵死：

- 检索层**不读取任何本地医院/科室/医生数据表**；
- 系统提示词明写"禁止凭记忆回答"；
- 检索失败时编排层**明告模型"本次未检索到任何结果"**，断掉编造源头；
- 护栏 R8 把"模型声称检索了"与"检索留痕"**逐条对账**，声称有结果但留痕空即判违规。

这意味着：**任何情况下，用户看到的答案要么来自真实联网检索、要么来自诚实的"没查到"——绝不会是写死的假数据。** 这就是生产环境里"稳定、顺畅、可信"的根。
