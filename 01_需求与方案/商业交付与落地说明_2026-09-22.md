# 商业交付与落地说明

> 作品名称：AI 医院资源查询与便民就医助手
> 文档版本：2026-09-24
> 配套证据：`使用与架构说明_赛题逐项对照_2026-09-21.md` ｜ `03_测试记录/`

---

## 一、定位

一个**不依赖任何付费接口、使用方只需自备一个模型密钥即可运行**的便民就医资源查询助手：真实联网检索公立医院与可核验民营医院的科室、医生、号源与院区资源，**每条结论都附可点击的真实来源链接；检索不到时明确说明未查到，不生成编造内容**。

该定位来自架构层面的选择：本作品不内置任何医院、科室、医生的事实数据，也不以预设答案替代动态查询结果。

---

## 二、适用对象与落地场景

| 角色 | 需求 | 契合点 |
|---|---|---|
| 地方卫健部门 / 政务服务平台 | 便民就医是政务服务高频场景，需要权威入口与可追溯来源 | 来源全部为可点击的真实公开链接，不编不猜，符合政务场景的可核验要求 |
| 医院宣传科 / 门诊办 | 将本院科室、专家、出诊、院区信息集中到一个对话入口，减轻热线压力 | 多后端检索可覆盖本院官网、挂号平台等公开信息；院区纪律（R10）保证不同院区信息不混用 |
| 县域 / 基层医疗联合体 | 基层群众不清楚「去哪看、找谁看」，需要对话式导诊 | 支持多轮补充条件（地区 / 院区 / 科室 / 日期），可承接上一轮继续查询 |
| 便民小程序 / 公众号运营方 | 在已有流量入口中增加就医助手能力 | `POST /chat` 接口可被小程序服务端直接调用（见第五节），无需改造前端 |

**适用范围说明**：演示范围设定为**昆明市**（赛题允许选定一个城市作为主要演示范围），**架构本身支持任意城市**——更换城市只需修改环境变量 `OPC_DEMO_CITY`，不绑定任何本地数据。本作品不声称已覆盖全国所有医院，而是明确说明：演示昆明、架构可泛化、来源以官方渠道为准。

## 三、部署路径

**部署特点：零额外配置即可运行。**

| 步骤 | 动作 | 使用方成本 |
|---|---|---|
| ① 获取 | 解压交付 ZIP（内含 51 个离线依赖轮子，无需联网安装依赖） | 0 |
| ② 启动 | 双击 `启动项目.bat`，自动打开 `http://127.0.0.1:8137` | 0（实测全流程 **25.2 秒**，相对 15 分钟的时间要求留有余量） |
| ③ 配置密钥 | 点击右上角「模型密钥」入口 → 选择服务商 → 粘贴**自备的**模型 Key | 1 个 Key（可选 13 家厂商之一） |
| ④ 上线 | 在政务云或内网启动服务进程，反向代理至域名即可对外提供服务 | 1 台普通服务器 |

- **不需要申请任何搜索接口**：检索走免密钥公开搜索页面（so360 / mso360 / sogou 三后端瀑布回退），使用方无需另行申请搜索 API 账号，也无需为搜索付费。
- **密钥不进项目**：模型密钥存于项目目录之外的外部密钥库（`%USERPROFILE%\.opc_health\keys.json`），不进代码、不进仓库、不进日志；交付包内置泄漏自检，并另有独立复验做逐字节扫描（密钥硬命中 0）。
- **未配置密钥也可启动**：进入「待配置模式」——页面正常打开、接口正常响应，但不发起检索、不调用模型，明确提示未配置并给出配置引导；填入 Key 后立即启用真实联网检索。

## 四、成本结构

| 成本项 | 金额 | 说明 |
|---|---|---|
| 检索成本 | **0** | 免密钥公开检索，不调用任何付费搜索 API |
| 模型成本 | 按量计费 | 使用方使用自备模型 Key，按服务商公开单价计费，与本作品无关 |
| 部署成本 | 极低 | 单进程 + 静态页面，1 台 2C4G 服务器即可；无数据库、无 Redis、无中间件 |
| 运维成本 | 低 | 进程内内存实现，重启即清空；无外部存储依赖，无备份负担 |
| 作品交付 | 一次性 | 作品本体 + 文档 + 测试证据，无订阅费用 |

> 本作品未接入付费搜索 API，也未引入向量数据库。这两项会增加使用方的配置与费用门槛，与「零配置上手」的目标相冲突。

## 五、与便民就医场景的适配

- **需求真实性**：群众常问「哪家有卒中中心」「某医生周几出诊」「急诊去哪挂」——均为高频且必须可核验的问题。
- **回答方式**：真实联网检索 → 四段式结构化输出（查询条件 / 查询结果 / 信息依据 / 使用提示）→ 每条附来源链接与时间 → 易变资源（血清 / 号源 / 床位）强制三态标注（「目前是否可提供尚待核实」）→ 院区纪律保证不同院区信息不混用。
- **安全边界**：诊断 / 用药意图（R4）明确拒答并引导就医；紧急症状（R5）优先提示 120；不输出「可预约成功」「确定出诊」这类无来源支撑的断言（R6）。
- **无法确认时**：不断言「没有」，而是给出官方渠道与可点击的手动检索入口；检索受风控影响时同样如此，不生成编造内容。

## 六、接入路径

本作品同时提供**网页入口**与**标准接口**，三种接入形态任选：

1. **独立网页**：直接部署 `index.html` 对话页，在政务云或内网访问。
2. **嵌入小程序 / 公众号 / App（webview）**：将对话页以 webview（网页视图）嵌入现有便民应用，无需改造。
3. **服务端调用接口**：现有小程序后端直接 `POST /chat`：

```json
// 请求
{ "message": "昆明哪家医院有抗蛇毒血清？", "session_id": "可选；首轮不传则返回新 id" }
// 响应
{
  "ok": true, "session_id": "s_xxx", "mode": "agent",
  "retrieval_log": [ { "action": "search", "query": "…", "status": "ok" } ],
  "output": { "query_condition": {}, "query_results": [], "info_basis": [], "usage_tips": [] },
  "error_code": null, "degraded": false
}
```

> 关于「小程序实际集成」：赛题明确该项不作为强制要求。本作品以**明确标注「模拟调用」的接口测试页**验证接入流程。

## 七、已知限制

| 限制 | 说明 | 应对 |
|---|---|---|
| 演示范围 | 默认昆明，非全国 | 架构支持任意城市（`OPC_DEMO_CITY` 切换），不绑定本地数据 |
| 来源时效 | 公开页面会更新或删除，链接可能失效 | 检索层只采用当前可访问的真实链接；R3 可选探测可达性；结论以官方渠道为准 |
| 检索稳定性 | 免密钥后端受搜索引擎风控影响，极端高频时会降级 | 多后端回退 + 总耗时预算（默认 18 秒）+ 明确的手动检索入口 |
| 无外部存储 | 会话与缓存均为进程内内存 | 单实例演示够用；如需多实例共享，会话层接口已预留（可替换为文件或 Redis） |
| 真实小程序集成 | 未实现 | 赛题允许；以标注「模拟调用」的页面验证接入流程 |

## 八、架构层面的保障

本作品从架构上避免「以预设答案冒充动态查询结果」，具体做法：

- 检索层**不读取任何本地医院 / 科室 / 医生数据表**；
- 系统提示词明确规定「禁止凭记忆回答」；
- 检索失败时，编排层**明确告知模型「本次未检索到任何结果」**，从源头排除编造；
- 护栏 R8 将「模型声称已检索」与「检索留痕」**逐条对账**，声称有结果但留痕为空即判违规。

因此在任何情况下，使用者看到的答案要么来自真实联网检索，要么是明确的「未查到」，不会是预置数据。
