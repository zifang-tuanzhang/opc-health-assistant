## 二、环境要求

| 项目 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10 / 11（64 位） | 离线依赖包 `wheels/` 为 Windows 64 位轮子 |

### 第一步：把源码取到本地

两种方式任选其一，效果相同：

**方式一 · Git 克隆（推荐）**

git clone <本仓库地址>

**方式二 · 下载 ZIP**

在仓库页面点绿色 `Code` 按钮 → `Download ZIP` → 解压到**任意目录**（路径含中文也可以，已实测）。

取到本地后，目录结构如下：

```
OPC接单吧第三届实战能力大赛/

├── 打包交付.py           （重新打包用，不用管）
├── wheels/               ← 51 个离线依赖轮子（保证不联网也能装起来）
├── 01_需求与方案/         （设计文档，可查阅）
├── 02_源码/               （全部源码）
│   ├── src/              （后端：编排层 / 护栏层 / 检索层 / 密钥层）

```

### 第二步：双击 `启动项目.bat`

启动器会自动完成四件事，全过程有中文进度提示：

1. 创建独立的 Python 虚拟环境（`.venv/`，不污染评审本机环境）；
2. **优先从 `wheels/` 离线安装依赖**（无需联网）；若离线包异常则自动回退在线安装；
3. 启动后端服务并等待健康检查通过；
4. 自动打开浏览器到交互界面。

看到下面这段提示即为成功：

```
  ✔ Python 就绪
  ✔ 依赖就绪
  ✔ 后端已启动
  · 打开浏览器：http://127.0.0.1:8137/
```

### 第三步：添加模型密钥（约 30 秒）

浏览器打开的界面顶部会显示「未配置密钥」。点击 **添加密钥** 按钮，三步完成：

1. 在厂商下拉框中选择你的模型供应商（预设已内置主流国内厂商）；
2. 粘贴你的 API Key（密钥，调用大模型用的凭据）；
3. 点击保存。

保存后页面顶部刷新为绿色，显示形如：

```
✔ 已连接：阿里云百炼（通义千问） / qwen-turbo
```

**密钥存在哪里？** 存在**项目目录之外**的个人目录：`%USERPROFILE%\.opc_health\keys.json`（即 `C:\Users\<你的用户名>\.opc_health\keys.json`）。

这样设计的原因：密钥永远不会被写进项目文件夹，因此**不会被误提交到版本库、也不会被打进任何交付包**。交付包内已做自动泄漏自检（见第八节）。

### 第四步：开始提问

在输入框里问真实问题，例如：

- `昆明哪家医院有抗蛇毒血清？`
- `云南省第一人民医院心血管内科怎么样？`
- `小孩发烧 39 度，该挂哪个科？`（会触发紧急就医提示）

界面上方会出现**检索进度时间线**（如「正在联网检索… → 命中 5 条 → 结构校验通过」），随后下方渲染四段式结果。

> **停止服务**：直接关闭那个黑色命令行窗口，或在窗口内按 `Ctrl + C`。

## 四、路径 B：Docker 容器启动

适合有容器环境、希望标准化部署的场景。

```bash
cd 02_源码/deploy
docker compose up -d
```

启动后访问 `http://localhost:8137/`。

| 场景 | 模型密钥怎么给 |
|---|---|
| 容器内没有用户目录，用不了外部密钥库 | 复制 `deploy/.env.example` 为 `deploy/.env`，填入 `OPC_LLM_API_KEY` / `OPC_LLM_BASE_URL` / `OPC_LLM_MODEL`，再 `docker compose up -d` |
| 只是想看骨架模式 | 什么都不填，直接 `docker compose up -d`（仍可真联网检索，只是不接大模型） |

> **搜索不需要任何密钥**。本作品走免密钥公开检索，`OPC_SEARCH_BACKENDS` 默认
> `so360,mso360,sogou,sm`（360 搜索桌面版优先 → 360 搜索移动版兜底 → 搜狗 → 神马搜索），
> `OPC_SEARCH_BUDGET_SECONDS` 默认 18 秒（单次检索外呼总耗时上限），无需申请任何搜索接口。
> 其中**桌面版与移动版是同一引擎的两个不同入口**，实测桌面版返回验证页时移动版仍能出结果，
> 因此互为冗余：多一次回退机会，仍能拿到**文章级**真实来源。神马搜索为独立运营方，与
> 360/搜狗不共用限流额度，故作为最后兜底。**如实说明：这是"提高上限"，不是"免疫"**——
> 本机持续高频自测时前几个入口先后都被风控过；正常使用（一次问若干问题）属中等量级，不受影响。
>
> **关于「引擎限流」**：搜索引擎在被高频请求时会返回「HTTP 200 但内容是安全验证页」。本作品对此做了三重处理：① 统一识别风控页并判该后端失败（否则会把验证页当结果解析，产出**编造来源**）；② 多后端自动回退；③ 结果缓存（10 分钟）+ 出站节流（≥1 秒）。取证与实测数据见 `03_测试记录/检索层风控与加固_2026-09-21.md`。

## 六、关键接口（供小程序 / 第三方接入）

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/health` | 健康检查：返回密钥状态、搜索后端、实时用量 |
| `POST` | `/chat` | 一次性问答：返回完整四段式结果 |
| `POST` | `/chat/stream` | **流式问答**（SSE，Server-Sent Events 服务器推送事件）：逐步推送检索进度，前端可显示「正在检索」 |
| `POST` | `/reset` | 清空某个会话的多轮上下文 |

请求示例：

```bash
curl -X POST http://127.0.0.1:8137/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"昆明哪家医院有抗蛇毒血清？","session_id":"demo-001"}'
```

完整接口契约（含字段定义、错误码表、微信小程序 `wx.request` 调用样例）见：
`01_需求与方案/小程序接口_2026-09-21.md`

项目内还附带一个**接口自测页**，可直接在浏览器里改造请求参数并查看原始返回：
`http://127.0.0.1:8137/static/小程序接口测试.html`

### 小程序接入注意事项

| 事项 | 说明 |
|---|---|
| 必须 HTTPS | 微信小程序正式环境只允许 HTTPS；本地 `http://127.0.0.1` 仅限开发者工具内关闭域名校验后调试 |
| 域名白名单 | 部署到公网后，需在小程序后台把域名加入 `request 合法域名` |
| 跨域 CORS | 服务端已内置白名单机制；正式部署时用 `OPC_CORS_ORIGINS` 配置，**禁止使用 `*`** |
| 超时设置 | 检索 + 生成耗时通常 5~15 秒，建议客户端超时设为 30 秒以上；或直接使用流式接口避免长时间白屏 |

## 七、零配置行为（评审不填密钥会怎样）

这是本作品的一条**诚实底线**，请重点验证：

| 状态 | 行为 |
|---|---|
| 未填模型密钥 | 进入**骨架模式**：接口正常返回、流程正常走通，但明确提示「未配置模型密钥」，**不会伪造任何答案** |
| 已填密钥但联网检索失败 | **不编造**：返回「暂未检索到可核验的公开信息」，并说明失败原因；`query_results` 与 `info_basis` 均为空 |
| 检索成功 | 结果逐条标注来源与链接，可点击核验；对易变资源（如抗蛇毒血清库存）强制标注信息状态 |

## 八、交付包自检与独立复验

交付包由项目根目录的 `打包交付.py` 自动生成，内置三道校验：

| 校验项 | 规则 |
|---|---|
| 关键文件齐全 | 逐一核对入口、源码、前端、测试、文档清单，缺一即报错 |
| 离线依赖完整 | 统计 `wheels/` 内轮子数量，为 0 即报错 |
| 密钥零泄漏 | 排除 `.env` / `keys.json` / `*.local.json`，并按文件名关键词（`密钥`/`secret`/`token`/`apikey` 等）二次拦截 |

重新打包：

```bash
python 打包交付.py
```

产物输出到 `04_交付物/OPC接单吧第三届_交付包_YYYYMMDD.zip`，脚本返回码 `0` 表示三项校验全部通过。

打包之后建议再做一次**独立复验**（不信任打包脚本的自报结果，直接读 ZIP 字节重新查一遍）：

```bash
python 复验交付包.py
```

它会检查：包内条目数与 CRC 完整性、敏感文件黑名单、字节级密钥扫描（从项目外密钥库装载真实密钥做比对）、离线依赖数量、以及包内每个 `.py` 的语法可编译性。返回码 `0` 表示通过。

## 十、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 `启动项目.bat` 窗口一闪而过 | 未安装 Python，或安装时没勾 `Add to PATH` | 重装 Python 并勾选该项；或先跑路径 C 看报错 |
| 提示「未检测到 Python 3.10+」 | 版本过低或路径未配 | 安装 3.10 以上版本 |
| 依赖安装失败 | 离线轮子与当前 Python 版本不匹配 | 启动器会自动回退在线安装；若仍失败，多为 Python 版本过新（如 3.14），建议换用 3.11 / 3.12 |
| 页面提示「未配置密钥」 | 正常状态 | 点「添加密钥」填入即可 |
| 顶部显示已连接，但回答没有结果 | 网络不通，检索失败 | 属**诚实降级**（不编造）；检查网络后重试 |
| 连续快速提问后被限速 | 每分钟模型调用上限保护 | 等一分钟即可；阈值可用 `OPC_LLM_RATE_LIMIT_PER_MIN` 调整 |
| 端口 8137 被占用 | 上次服务未正常关闭 | 关闭旧命令行窗口，或改 `OPC_PORT` 换端口 |

### 关于「搜索引擎限流」的补充说明（如实告知）

本作品用的是**免密钥**的公开搜索引擎。做自测时本人短时间发了大量检索请求，触发过搜索引擎的风控（返回 HTTP 200 的"安全验证页"）。处理方式：

1. 检索层会**识别风控页**并判该后端失败（避免把验证页当结果解析、产出编造来源）；
2. 自动切下一个后端；并提供 10 分钟结果缓存 + ≥1 秒出站节流；
3. 三个默认后端都不可用时，**诚实降级**为"暂未查到"，并附上**可点击的手动检索入口**（把搜索引擎的查询地址给用户，让他自己一点就能看）。
4. 针对"桌面版被风控"，额外把 **360 搜索移动版** 也接成了后端——桌面版与移动版是同一引擎的不同入口，桌面版返回验证页时移动版仍正常出结果，等于给主力来源加了一次回退机会（**提高上限，非免疫**：持续高频下两个入口会先后被风控）。

> 正常使用（一次问几个问题）不会触发限流。完整取证见 `03_测试记录/检索层风控与加固_2026-09-21.md`。
