## 2. E3 检索留痕对账（防"声称检索其实没检索"）

真实问答 `昆明哪家医院有抗蛇毒血清？` 的运行结果：

```
ok=True  mode=agent  reflection_count=1
retrieval_log=[('search', 'ok', 5), ('guardrail', 'reject', 3)]
[PASS] E3 声称有结果 ⇔ 留痕有命中 | 声称有结果=True / 留痕命中=True
```

- `('search','ok',5)`：确实发起检索并命中 5 条；
- `('guardrail','reject',3)`：**护栏真的打回了 1 轮**（3 处违规，即 3 条结果缺三态标注）；
- 对账逻辑（护栏 R8）：**只要产出里有结果/来源，检索留痕就必须真有命中**，
  否则判"涉嫌以记忆冒充联网检索"。这条把"假装搜过"堵死了。

> 真机界面上的同一幕（见 `截图/验收_G2_抗蛇毒血清三态.png`）：

## 3. E2 失败处理取证（红线：检索不可用时**零编造**）

**做法**：把检索后端临时置为不可用（`config.SEARCH_BACKENDS = ['__offline_for_test__']`），
仍走**真实的 `web_search` 代码路径**，因此必然返回空；然后看模型怎么答。

**运行结果原文**：

```
ok=True  mode=agent  degraded=False
retrieval_log=[('search', 'empty', 0)]
结果条数=0 依据条数=0
usage_tips=["暂未查到可核验的联网信息，请以医院官方渠道为准"]

[PASS] E2 零编造（结果/依据皆空） | 结果=0 依据=0（红线：不得编造）
[PASS] E2 如实告知（含诚实标志） | 命中诚实标志=['未查到', '暂未查到']
```

**这条为什么是"红线级"证据**：

- 检索**明明失败**（0 命中），但模型**没有**用训练记忆"补"出医院名和链接——
  `query_results` 与 `info_basis` 都是空数组；
- 反而**主动如实告知**"暂未查到可核验的联网信息，请以医院官方渠道为准"；
- 这正是赛题**严禁的"冒充动态查询"**的反面：**查不到就说查不到**。

对比一下修复前的老问题（本会话曾真实出现、已修）：
早期版本在检索为空时，模型仍"编"出了带医院官网 URL 的 sources，
而 `retrieval_log` 只记了 `empty`——**看起来在检索、其实在编**。
现在由「系统提示硬约束 + 编排层显式告知"未检索到" + 护栏 R8 对账」三层堵住。

## 5. 诚实标注的局限

1. **检索源为公开网页**（360搜索 / DuckDuckGo），不是医院实时业务系统；
   因此"当前是否能提供"必须标三态并由用户电话核实——这是**设计取向**，不是缺陷。
2. **本环境实测**：DuckDuckGo 被网络拦截、Bing 返回降级页，故**当时**的默认顺序为 `so360,ddg`（后续版本已改为 `so360,mso360,sogou`，ddg 不再默认启用）；
   在海外网络可把顺序调成 `ddg,so360`（环境变量 `OPC_SEARCH_BACKENDS`）。
3. **E1 的"检索成功"依赖取证当时网络可达**；不可达时会走 E2 路径（不崩溃、不编造）。
4. 上述证据**不证明**任何一家医院今天真的有某种资源——那只能由医院官方渠道核实。
   系统给出的价值是：**把可核验的公开线索与时间/来源一起摆出来，并诚实标注不确定性**。
