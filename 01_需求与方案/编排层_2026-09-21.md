## 0. 失败复盘（上届·AI智能营养顾问）
- 表象：安全满分，但险些无评分资格，最终"优秀奖=倒数第一"。
- 根因：代码层怕模型出错，堆**硬编码事实分支** + 把模型权限压到极小 → 模型零思考空间。
- 本届铁律：**模型当控制器；事实（医院/科室/医生/排班/资源）绝不可硬编码；规则/边界/校验可以代码写**（见第3节，这是纠正上届的核心）。

## 1. 赛题对实现方式的硬约束（旧路子直接出局）
- "基础功能必须包含**真实联网检索**及智能体对用户请求的**动态处理**"。
- "不得通过**硬编码医院答案或预设对话**冒充动态查询"。
- "规则可用于**参数校验、模板呈现和边界控制**，但不得通过硬编码事实冒充动态查询" ← 这条界定了代码能写什么。
- 推论：必须 Agent 编排，模型当控制器；代码只给 tools + 原则 + 输出契约 + 允许的轻量规则。

## 2. 编排层设计（4层，已强化）

### 2.1 原则层（系统提示词里的原则，不是规则树）
- 角色：医院资源查询与便民就医助手。
- 主动联网检索，不靠模型内部记忆答医院事实。
- 来源可核验：权威渠道（医院官网/官方公开页/卫健委）优先；补充来源须注明性质与核验情况，**不把搜索摘要直接当已核实事实**。
- 不编造：查不到标"未查到/待核实"，**绝不断言"医院没有该科室/医生/资源"**。
- 区分三态（核心真实性得分点）：`历史上有相关报道` / `公开页面介绍具备相关能力` / `目前是否可提供尚待核实`（特殊资源如抗蛇毒血清必标，不得把历史储备/采购/救治报道等同当前库存或可立即使用）。
- 边界拒答：不诊断、不治疗、不用药、不处方指导；遇紧急求助**优先提示联系当地急救（120）**，不以继续搜索替代。
- 时效诚实：不把抓取日期当更新日期；来源未标日期写"**来源未标注更新时间**"。
- 院区纪律（**2026-09-21 补入实现**）：医院有多个院区时，每条结果标明**适用院区**（地址/科室/医生/出诊排班分别属于哪个院区）；不同院区的信息不得混用、也不得合并成一条；来源未标明则写"来源未标明院区"，**不得自行推定**。
- 条件澄清（**2026-09-21 补入实现**）：要查医院/科室/医生/资源但**未说明地区**、且同一会话上文也没有时，**不检索、不推定地区**，先询问用户所在城市或地区；用户补充后再检索。**演示范围不得代替用户给出的条件**。

### 2.2 能力层（工具 tools，模型按需调用）
- `search(查询词, 城市)`：真联网检索，返回 `标题/链接/摘要/来源性质(权威|补充)`。
- `fetch(url)`：取网页正文（遵守访问规则，不绕过登录/权限）。
- `session(读/写/重置)`：多轮上下文、会话隔离、重置。
- `retrieval_log`（新增·第一类公民）：每次 search/fetch 的 `查询词/调用状态/返回来源` 留痕，供前端实时展示（满足基础1"展示检索关键词+调用状态+来源记录"、基础7"检索中显示状态"）。

### 2.3 控制循环（模型驱动，不是代码分支）
理解意图 → （演示范围固定昆明，地区不视为缺失）判断缺失条件是否影响检索 → 不影响则直接按范围检索；影响则规划检索词前先澄清（模型声明 `need_clarification`）→ 调工具 → 从来源提取事实并关联链接+时间+来源性质 → 冲突标出 → 按4段式契约产出 → 多轮承接。

> **实现说明（2026-09-21 二次重构）**：原设计首步「补全省缺条件（问城市/科室/日期）」曾被实现成**教条式硬编码**——25 词词表猜用户/模型措辞 + 台词模板"请问您要查哪个城市或地区"。
> 这违反"判断优先于指令"原则（变化维度大，写死必漏；且项目定位昆明，反问城市既多余又会在用户答外地时答不了）。
> 现改为**给判断/给事实**：地区作为固定事实注入（不问）；缺科室/医院/资源等真实条件时，模型自决并**显式声明 `need_clarification` 字段**，代码读字段判定（不猜措辞）。
> 详见方法论技能 `judgment-over-instruction`。

### 2.4 护栏层（反射式校验打回循环 · Reflection Guardrail Loop）

> 核心机制（回答"要不要加硬编码输出拦截"）：模型产出后，代码做**结构性/契约性校验**（只查"左侧"规则，不查事实真假）；不通过就**把违规点与提醒编码回灌给模型**，模型重新组织语言后再输出——形成"生成→校验→打回→再生成"循环。**模型始终是控制器，代码只给"镜子+提醒"，绝不替模型写事实、绝不预设对话**（这正是上届死因的精准纠正）。

- **2.4.1 静态标注（兜底，原校验①②③）**：每条事实 claim 须带来源链接+性质；出诊硬约束；框架填充禁止——详见 2.4.3 规则集，校验不通过时在输出内标注，但这只是兜底。
- **2.4.2 主动打回循环（新增·建议升为基础必做）**：
  - `Validator`（代码，纯左侧）：输入模型 response（4段式 schema），输出 `{ pass: bool, violations: [{rule, field, detail}], hints: [str] }`。规则集见 2.4.3。
  - `Reflector`（代码→模型回灌）：`pass==false` 时，把 `violations + hints` 拼成**结构化反思指令**回灌进 messages（作为修正提示），模型下一轮带着约束重新生成。反馈措辞由代码生成、执行由模型完成——**不是重新检索，是重新组织语言/指出问题**。
  - `Loop Controller`：最多打回 **N=2 轮**；每轮写入 `retrieval_log`（透明："护栏打回×k：缺来源/越界"）；超 N 轮→**降级输出**（带"⚠️未完全满足全部约束"提示），仍交付不崩溃、不卡死。
- **2.4.3 Validator 规则集（全部"左侧"，代码可写）**：
  - R1 结构完备：4段式字段齐全、非空壳。
  - R2 来源必填：每条 result 必须带 `source(title+url)`，url 合法 http(s)。
  - R3 来源可达（可选）：打回时轻量 HEAD/GET 探测 url 可达；不可达→violation"链接不可访问，请换源或标待核实"。
  - R4 边界拒答：用户问诊断/用药/治疗，response 不得含诊断结论/用药建议，违则 violation。
  - R5 紧急优先：检测到紧急词（胸痛/昏迷/大出血/轻生倾向…），response 必须含"请立即拨打120"，否则 violation。
  - R6 禁断言：response 不得含"目前可提供/有号/可预约成功/确定出诊"等无检索支撑断言（对应出诊硬约束 D），违则 violation。
  - R7 空字段诚实：无来源字段须标"未查到/待核实"，不得留空或编造，违则 violation。
  - R8 检索真实性：response 声称"已检索"须与 `retrieval_log` 一致，防模型谎称检索，不一致 violation。
  - R9 易变资源三态：用户问到血清/血库/床位/号源等易变资源时，每条结果必须标 `info_status` 三态之一。（**2026-09-21 补记**）
  - R10 院区纪律：用户提到院区（命中通用院区词）时，每条结果必须标明**适用院区**（`campus` 字段，或名称/说明中已写清）。（**2026-09-21 补记**）
  - **澄清轮豁免（`clarify=True`）**：R1 与 R7 在**条件澄清轮**豁免——正在问用户"要查哪个城市"时，条件本身就是缺的、本来就没有结果；**但不豁免编造**（澄清轮若塞了结果，仍被 R8 打回）。（**2026-09-21 补记**）
  - 🔴 **红线（Validator 的硬边界）**：上述只校验**结构/契约/边界词触发**，**绝不判断事实真假**（如"昆医附一是否真有心血管内科"）——事实真假只能靠来源链接+人工/评委核验。越过这条=重蹈上届"代码判断事实"的坑。
- **2.4.4 打回反馈格式（代码生成、模型执行）**：
  - 示例：`【护栏拦截·第2轮】检测到违规：① 第2条结果未附来源链接（R2）；② 你写了"该院目前有号"（R6，违反出诊硬约束）。请：(a)为该结果补上可核验官方来源链接，或(b)改为"暂未查到可核验的出诊安排"。重新组织语言后输出，勿编造。`
- **与上届本质区别**：上届"代码发现违规→代码写答案"（模型被架空，死）；本届"代码发现违规→代码说哪违规→模型自己改"（模型始终掌权，活）。打回循环是"我们真做了护栏、且没硬编码"的最强可演示证据。

## 3. 🔴 可硬编码 vs 不可硬编码边界（纠正上届的核心）
赛题明确"规则可用于参数校验、模板呈现和边界控制"。据此划定：

| 代码层可写（安全，不犯红线） | 代码层禁写（=上届死法，一票否决） |
|---|---|
| 参数校验：空输入/超长/格式/超时判定 | 任何具体医院名/科室名/医生名 |
| 边界触发词：诊断/用药/紧急→提示模型拒答或120 | 任何出诊排班/号源/擅长领域事实 |
| 模板：4段式输出结构、字段形状 | 任何"预设对话"或对答脚本 |
| 来源性质标注逻辑（权威/补充判定词表） | 任何"某医院有某资源"的结论 |
| 检索失败/异常的统一提示文案 | 任何硬编码的检索结果 |
| Validator 校验规则（结构/契约/边界词触发，属"左侧"） | Validator 校验事实真假（属"右侧"，禁写·见2.4.3红线） |

> 上届错在把右侧（事实）也写进了代码 → 模型零空间。本届只把左侧（规则/边界/校验）写进代码，**事实全部由模型从真实检索来源产出**。

## 5. 拉满增强方案（缺口 A~H + 进阶）

**A. 检索过程可观测**（基础1/7）：`retrieval_log` 作为第一类公民数据结构，前端在检索中实时渲染"检索词→调用中→返回N条来源(权威/补充)"。这是评委现场换条件查时最直观的"真联网"证据。

**B. 来源性质标注**（基础1）：schema 来源加 `source_type: 权威|补充` + `核验状态`；补充来源明示"未经官方核实"。

**C. 边界清单显式化**（基础4）：系统提示词+护栏触发词表明确含"费用/医保/交通/办理条件无来源不自行补齐"与"诊断/治疗/用药拒答"。

**D. 出诊硬约束**（基础3）：护栏校验②——无来源日期的出诊陈述、从往期推断当前/号源/预约成功，一律拦截改写成"暂未查到可核验的出诊安排"+官方挂号引导。

**E. 输入护栏**（基础7，代码写、安全）：空输入/超长(如>500字)/无关(意图不在医院资源域)/接口超时/搜索失败 → 统一提示+重试入口。属第3节"左侧"允许硬编码。

**F. 框架填充禁止**（基础5）：护栏校验③——4段式空字段必须标"未查到/待核实"，绝不为填满而编造。

**G. 信息状态三态**（基础2/核心真实性）：schema 每条资源/医生结果带 `信息状态 ∈ {历史报道, 公开介绍具备能力, 目前可提供尚待核实}`，特殊资源强制三态之一。

**H. 进阶纳入编排**（拉满分项）：进1交叉核验+过期提醒、进2手机界面+比较、进3持久化+限流重试+降级——均在编排层预留接口/契约，实现按48h时间窗取舍但设计不留白。

## 6. 文档编排（4段式输出契约升级）
代码定义输出契约(schema)，模型从真实来源填内容，渲染层出卡片/表格：
```
{
  查询条件: {地区, 医院/院区, 资源/科室, 医生条件, 查询日期},
  查询结果: [{
    医院全称, 院区, 类别, 匹配资源, 匹配依据,
    信息状态: 历史报道|公开介绍具备能力|目前可提供尚待核实,
    涉及医生: [{姓名, 科室, 职称, 擅长领域(忠实概括), 出诊:{类型:周期|排班, 院区, 日期/周期, 来源时间}}],
    来源: {标题, 链接, 来源性质:权威|补充, 更新时间(如有), 查询时间}
  }],
  信息依据: [来源明细],
  使用提示: [未核实/过期/冲突说明, 官方核实或预约方式]
}
检索过程: retrieval_log[]  // 独立展示，不混入答案
```
- 代码管结构+来源必填+三态枚举+框架填充禁止；**不管具体事实，绝不写死**。
- 契约稳定、内容动态 = 编排，非硬编码。

## 7. 执行前置（待项目负责人落实）
- 项目负责人提供搜索/模型 API 密钥（服务端环境变量，不暴露前端/仓库/日志/对话）。
- 真联网连通性验证（真实发一次昆明医院搜索）→ 任务清单 → 骨架 → 按本矩阵逐条实跑(先补△缺口，再做✗进阶) → 8组测试(覆盖第4节清单) → 交付。
- 测试场景覆盖（基础7硬要求）：医院资源 / 医生信息 / 出诊时效 / 多轮条件变更 / 无结果或来源不可访问 / 特殊资源未核实 / 诊疗越界 / 小程序接口或模拟调用。
