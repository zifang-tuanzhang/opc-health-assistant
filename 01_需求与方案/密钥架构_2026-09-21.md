## 一、背景与目标（项目负责人原始要求提炼）

项目负责人要求：评审把代码拉到本地后，**只点「添加密钥」就能用**，不能去翻文件找密钥；密钥**绝不能跟着项目一起存放**（否则"项目失败"）；项目的环境依赖要在目录内**形成闭环**（不依赖下载，避免下载失败）；**启动器要能拉起整个项目**（后端 + 前端），且用**中文命名**。

逐条对齐的目标清单：

| 项目负责人要求 | 本架构的落地方式 |
|---|---|
| 评审免翻文件添加密钥 | Web「添加密钥」弹窗 + 预设厂商下拉 + 粘贴即连 |
| 密钥不随项目存放 | 密钥库放在项目外部 `%USERPROFILE%\.opc_health\keys.json`，git 碰不到、ZIP 不带 |
| 环境依赖目录内闭环 | `wheels/` 内置离线安装包（cp311/312/313 win_amd64）；启动器优先 `--no-index` 离线装 |
| 启动器拉起整个项目 | `启动项目.py` + `启动项目.bat`（中文命名）：建 venv → 离线装依赖 → 起后端 → 开浏览器 |
| 评审摩擦最小 | 搜索用**免密钥**的公开检索（360 搜索 + 搜狗，详见 2.5），评审只需 **1 个模型密钥**即可端到端跑通 |

**结论：项目负责人的四点要求全部可达。** 下面给出设计、文件清单、使用流程与验证证据。

## 二、设计决策（6 大支柱）

### 2.1 预设厂商清单（随源码发货，不含任何密钥）

- 文件：`02_源码/keys/providers.preset.json`
- 内容：13 个主流国内厂商（DeepSeek / 通义千问 / 智谱 / 豆包 / 混元 / Kimi / MiniMax / 千帆 / SiliconFlow / StepFun / 星火）+ OpenAI 兼容 / 本地 Ollama。
- 每个厂商只存**配置元数据**：`vendor`（中文名）/ `base_url`（网关地址）/ `default_model` / `homepage` / `wire: openai` / `auth: bearer`。**绝不存密钥值**。
- 设计理由：所有国内厂商都是 OpenAI 兼容（与 OpenAI 接口规范一致）网关，后端只需一套 `openai` SDK（软件开发工具包），按 `base_url` 切换。评审点开下拉就能选，不用手填网关。

### 2.2 外部密钥库（项目外、git 碰不到、自动扫描）

- 代码：`02_源码/src/keystore.py`
- 固定位置：`%USERPROFILE%\.opc_health\keys.json`。
- 铁律：密钥**只读写这个外部文件**，绝不写回项目任何位置；即便把整个项目打成 ZIP（压缩包）发出去，密钥也不随行。
- 后端每次启动 / 每次请求都**自动扫描**这个固定位置——有有效密钥就直接连接（项目负责人所述「自动扫描」）。
- 提供的函数：`is_configured()` / `get_active()` / `upsert_provider()` / `set_active()` / `list_configured()` / `store_path()`（把库路径告诉评审，透明可查）。

### 2.3 Web 添加密钥页 + 自动扫描路由（连得上才写）

- 代码：`02_源码/src/keys_routes.py` + `02_源码/static/index.html`
- 路由（前缀 `/api/keys`）：
  - `GET /providers` —— 给「添加密钥」界面的下拉清单（不含密钥值）。
  - `GET /status` —— 后端自动扫描外部密钥库的结果（连没连上、存在哪）。
  - `POST /add` —— 选厂商 + 粘贴密钥 → **真连一次校验**（`test_connection`，`max_tokens=1` 极小调用）→ 成功才写入外部库；失败返回 `400` 并说清原因，**绝不写入**。
- 前端：暗色主题聊天界面，`index.html` 内含「添加密钥」弹窗（厂商下拉 + 模型名 + 密钥输入框 + 状态横幅），全程不碰文件。

### 2.4 启动器闭环（中文命名，一键拉起）

- 文件：`启动项目.py`（主逻辑）+ `启动项目.bat`（纯 ASCII 入口，避免 GBK 乱码导致进程秒退）
- 流程：
  1. `find_python()` 找 ≥3.10 的 Python；
  2. `bootstrap_venv()` 建 `.venv`，优先 `pip install --no-index --find-links wheels/` **离线装**（无网也成），失败才回落在线装；
  3. `start_backend()` 用 uvicorn（ASGI 服务器）起 `src.server:app`，监听 `127.0.0.1:8137`；
  4. `wait_ready()` 等健康探测通过；
  5. `webbrowser.open()` 自动开浏览器到交互界面。
- 命名：按项目负责人要求全程中文（`启动项目`），评审双击 `.bat` 即活。

### 2.5 免密钥搜索（评审只需 1 个模型密钥）

- 代码：`02_源码/src/search.py`
- 真实联网检索走 360 搜索（桌面版 + 移动版）与搜狗搜索的公开页面，**不需要任何 API 密钥**。
- 价值：评审**只要填 1 个模型密钥**（跑通大模型回答），搜索环节零密钥也能真联网——大幅降低评审摩擦，且搜索结果真实可核验（满足赛题"真实联网、不硬编码"红线）。
- 失败兜底：检索静默降级返回空列表，绝不编造。

### 2.6 依赖闭环（vendored wheels）

- 目录：`wheels/`（45 个包，15MB，cp311/312/313 win_amd64）
- 含：fastapi / uvicorn / pydantic v2 / openai / httpx / python-dotenv 等。
- 已实测：新建空白 `.venv_test`，`pip install --no-index --find-links wheels/` → 全部装成，`openai 3.16.2` 确认。评审**断网也能装**。
- `.gitignore` 排除 `.venv/` / `.env` / `*.local.json`，但**保留 `wheels/`**（属交付闭环的一部分）。


### 5.4 真实千问密钥联调（项目负责人提供临时密钥，A 步验收）

- 项目负责人提供千问（通义千问）临时密钥，经架构入口写入外部密钥库（`%USERPROFILE%\.opc_health\keys.json`），激活 `qwen / qwen-turbo`。
- 连接校验：`test_connection` 到 DashScope（阿里云百炼）兼容网关 → `ok=True | 连接成功`。**证明密钥有效、网关正确、连接校验逻辑正确。**
- 端到端 `run_turn("昆明哪家三甲医院有心血管内科？")` → `ok=True, mode=agent, degraded=False`，产出真实 4 段式（region=昆明）。
- **直接回答项目负责人的两个判断**：
  1. *"没活是不是逻辑没写对？"* → 活了，逻辑正确。若当时没活，优先排查：密钥失效/模型名错/`base_url` 错/网络，而非核心逻辑——因为连接与编排路径是供应商无关的通用实现。
  2. *"是不是其他供应商也活不过来？"* → 不会。所有厂商走同一套 OpenAI 兼容（与 OpenAI 接口规范一致）客户端 + `test_connection` 通用校验；千问通即证明该通用路径正确。某厂商"活不过来"只可能是**该厂商预设的 `base_url`/模型名写错**（配置问题，非逻辑），或该厂商密钥/网关本身问题。
- 诚实发现（已在联调中修复）：早期检索层依赖 DuckDuckGo，而本沙盒网络下它不可达（SSL 超时）、Bing/百度返回反爬降级页，故「真联网检索」一度取不到真实结果；原编排在检索为空时仍让模型编出带 URL 的 sources（冒充动态查询，**踩赛题红线**）。**已修复两件事**：① 检索层改为 360 搜索（桌面版/移动版）+ 搜狗，实测可取到真实文章级来源；② 检索为空时编排层显式告知模型"未检索到"，模型须返回空 results/sources + "暂未查到可核验信息"，**不编造来源**（详见 5.5 与六.1）。

### 5.5 诚实护栏（检索为空不编造）验证

- 同环境再跑 `run_turn`（检索仍为空）→ `query_results=0, info_basis=0`，usage_tips=`暂未查到可核验的联网信息，请以医院官方渠道为准`，**未编造任何来源 ✅**。
- 该护栏与搜索后端无关：无论评委机器能否联网，只要检索为空，模型都诚实降级，不触红线。

## 六、诚实标注的局限（项目负责人要求：做不到要强调）

1. **真实 Agent 循环已用千问真实密钥端到端验证（模型调用→4 段式生成通过）**，且**真联网检索已取到真实医院来源**（见 `03_测试记录/真实性证据_2026-09-21.md`：360 搜索实网返回文章级 URL）。**仍存在的边界**：免密钥后端都是别人的公开页面，持续高频请求下会被风控（本机自测中三家先后触发过，见 `检索层风控与加固_2026-09-21.md`）；正常使用量级不受影响，极端情况会走「检索为空→诚实降级不编造」护栏（5.5）。如要进一步保障，可在密钥库增一个 search 类供应商走付费搜索 API（SerpAPI/Brave Search/Bing Web Search），本函数签名不变，属可选增强。
2. ~~**反射式打回循环（Validator/Reflector/LoopController，N=2）尚未接入代码**~~ → **已接入并实测通过**（2026-09-21 复核）：`orchestrator.py` 内已有完整的"打回—重生成"循环（最多 N=2 轮；仍不通过则降级交付并带 ⚠️，不崩溃），护栏层测试中含 `[PASS] N6 解析失败可打回 note=护栏打回 1 轮后通过`。
3. **`wheels/` 仅含 Windows（win_amd64）轮子**：评审环境按 Windows 交付；若需在 macOS / Linux 跑，需补充对应平台轮子或走在线装（启动器已带在线回落）。
